# 常见问题与处理顺序

## 安装包不符合系统要求

确认选择的是 Release 内的 `.fpk`，不是 APK、源码 ZIP 或整个下载目录。需要 fnOS 1.2.0401+ 与 Node.js v22。核对下载文件 SHA-256，并保留具体安装日志。

当前公开包**未签名**。若设备策略要求开发者签名，需要真实飞牛开发者证书构建；重命名文件不能增加签名。本项目不提供绕过系统校验的方法。这个错误是通用提示，没有设备日志不能断定唯一原因。

## 飞牛文件管理能看到 SD 卡，DIT 没有

点击 **选择存储卡**，从“外接存储”选择卡根目录或 DCIM 并授权，再刷新。DIT 会区分没有设备、已断开、没有 DCIM 和读取权限不足。文件管理的当前登录用户与 DIT 专用应用账户权限不同。

若仍不可读，先检查系统设置中 DIT 的目录授权，再参考 [SD 卡排查](SD_CARD.md)。飞牛某些外接文件系统还受外接存储可见范围影响；“所有账号可见”会扩大到其他 NAS 账号，应按共享需求自行决定，软件不自动更改。

## 识别到文件却没有导入

确认已选择归档目标并保存，目标是 NAS 内部可写目录，自动导入已开启并保存。也可手动点击立即扫描。读取工作状态和历史中的数量：

| 结果 | 含义与操作 |
| --- | --- |
| 待稳定 | 尚未连续观察到足够的无变化时间；等待后重扫，检查稳定等待设置 |
| 重复 | 内容已有归档，本轮没有再复制，核对日志里的目标 |
| 失败 | 打开本轮日志，检查读取、写入、空间和复制校验错误 |
| 新增 | 本轮成功提交的文件数，去目标目录核对 |

文件持续变化会重新计时。v0.1.4 起不再以文件时间是否早于 NAS 当前时间判断稳定；无需修改原卡时间来绕过等待。

## 卡已完成，又新增了照片但没有自动扫描

当前版本会在卡已完成且仍连接时跳过重复自动处理。点击“立即扫描一次”重新检查，或在飞牛中安全推出后重新插入。不要在正在导入时拔卡。

## 部分文件日期不正确

拍摄时间解析依赖格式与元数据，有些 RAW/HEIC/视频会回退文件 mtime。检查相机时间、分类时区和日志中的日期来源；必要时通过 ExifTool 核对样本。本项目不自动修改原文件元数据。

## 日志显示 UTC+8，但照片目录仍不符合预期

运行日志和扫描计划固定东八区；照片分类使用设置中的日期时区，两者是不同用途。确认拍摄元数据、相机时间及日期显示时区。

## 修改目标后没有复制第二份

去重按内容索引判断，索引里原目标存在且校验一致时可能继续判定重复。切换目标不等于制作第二份独立备份。不要为复制第二份贸然删除索引；应使用备份工具完成多副本需求。

## 为什么没有下次扫描时间

自动导入关闭时没有计划；运行中要等本轮完成再安排；重新保存配置会更新计划。请确认保存成功，观察状态和后台是否正常运行。

## 重启后如何查每次导入了多少

打开“导入历史”。支持该功能之后的每轮数量会保存到应用数据，正常重启后保留。旧版 `import.log` 仍可下载，但不会推测成每轮数量表。已中断记录只代表最近保存的检查点，应核对目标后重新扫描。

## 日志写入失败或存储空间不足

先关闭自动导入，保留错误信息，检查应用数据所在卷和归档目标所在卷的可用空间及权限。不要删除唯一照片副本来腾空间。日志无法保存时界面会提示，不应把该轮记录当作完整审计。

## 提交问题需要什么

提供应用版本、fnOS 完整版本、浏览器/客户端版本、操作步骤、历史汇总、相关错误行，以及可复现的少量非敏感样本。日志中的账户名、完整目录或文件名可先脱敏；不要提交密码、token 或证书私钥。
