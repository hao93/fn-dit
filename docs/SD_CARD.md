# 飞牛已识别存储卡，但 DIT 没有设备

v0.1.3 针对用户的 `外接存储 → SD_Card_Reader → DCIM → 133_FUJI` 布局修复识别与提示；保留 v0.1.2 的原生目标目录选择。

## 使用新版

1. 应用中心手动安装新版 FPK，覆盖升级，保留原有配置。
2. 在外接设备卡片点击「刷新设备」。已挂载但未授权、不可读、找不到 DCIM、之前保存的卡已拔出，会分别显示原因。
3. 若飞牛能看到 SD 卡而应用未发现，点击「选择存储卡」，在飞牛原生弹窗的「外接存储」中选择 `SD_Card_Reader` 根目录或它的 `DCIM` 文件夹，确认授权。不需要复制路径。
4. 通过目录读取检查后，来源会自动保存，显示检测结果。归档目标仍通过「选择文件夹」单独配置，再点击「保存配置」。两者不会相互替换。
5. 保持自动导入关闭，先用少量测试文件点击「立即扫描一次」。

## 仍提示读取权限不足

飞牛文件管理以当前 NAS 登录用户显示文件，DIT 后台以独立应用账户运行，两者的访问权限不同。

先在「系统设置 → 应用 → 飞牛 DIT」授权这张卡的目录。对于 FAT/exFAT/NTFS 等外接盘，系统挂载权限可能仍限制应用账户访问。飞牛官方帮助对这类问题提供的处理是：在「文件管理 → 设置 → 外接存储权限」中检查设置，必要时改为「所有账号可见」，再重新保存应用目录授权。

**「所有账号可见」会让其他 NAS 账号也能看到外接盘。** 应根据共享需求自行决定；程序不自动改挂载参数、权限、属主，不切换为 root 或其他用户绕过访问控制。

[飞牛官方说明](https://help.fnnas.com/articles/v1/media/filepath)

## 已修正的代码问题

- 原逻辑要求读取 `/sys/class/block/...` 并确认 USB/MMC 才显示设备。设备别名或 sysfs 不可访问会被误判为没有卡。
- 现在识别外接目录下的本地文件系统，不再把硬件探测失败当成挂载不存在；内置卷、系统路径、远程挂载和 loop 设备不纳入自动扫描。
- 原来的读取异常被静默忽略。现在把「设备已发现但不可读」与「无设备」区分显示，并提供明确刷新结果。
- 支持直接选择 DCIM 或其中的相机子目录，不再只查找“子目录里的 DCIM”。相同 DCIM 自动去重。
- 读取目录嵌套的上限由前 20 项增至 256 项；保存的来源在拔卡后仍保留并提示断开。
- 原生存储卡选择使用同一个官方目录选择器，限定外接存储侧栏；回调绑定选择用途，避免覆盖归档目标。

本地测试包含用户截图对应目录树及模拟权限不足、设备别名、未读到 sysfs、大小写 DCIM、拔卡、远程挂载排除等情形。未连接用户 NAS，不能声称已查到设备上的唯一原因或已经实机恢复。
